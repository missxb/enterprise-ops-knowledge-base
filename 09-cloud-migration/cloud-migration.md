## 2. 上云评估与规划

### 2.1 TCO分析模板

```bash
# TCO (Total Cost of Ownership) 分析

# ===== IDC成本 =====
# 硬件采购（按3年折旧）
# - 服务器: 20台 × ¥50,000 = ¥1,000,000
# - 存储: 100TB × ¥2,000/TB = ¥200,000
# - 网络设备: ¥300,000
# 硬件折旧: (1,000,000 + 200,000 + 300,000) / 36 = ¥41,667/月

# 机房费用
# - 机柜: 4个 × ¥8,000 = ¥32,000/月
# - 带宽: 100Mbps × ¥5,000 = ¥5,000/月
# - 电费: ¥10,000/月

# 人力成本
# - 运维人员: 3人 × ¥20,000 = ¥60,000/月

# IDC总成本: ¥41,667 + ¥32,000 + ¥5,000 + ¥10,000 + ¥60,000 = ¥148,667/月

# ===== 云上成本（估算） =====
# ECS: 20台 × ¥2,000/月 = ¥40,000/月
# RDS: 2台 × ¥5,000/月 = ¥10,000/月
# Redis: ¥3,000/月
# SLB: ¥2,000/月
# OSS: ¥1,000/月
# 带宽: 100Mbps × ¥3,000 = ¥3,000/月
# 云上总成本: ¥59,000/月

# 节省: (148,667 - 59,000) / 148,667 × 100% = 60.3%

# 注意: 以上为示意，实际需要根据业务规模精确计算
# 使用阿里云TCO计算器: https://www.aliyun.com/price/product
```


```yaml
#   - NONE (默认拒绝所有)

# 入站:
#   - 6379/TCP: sg-app
# 出站:
#   - NONE

# 入站:
#   - 22/TCP: 办公IP/VPN
```

## 6. 数据迁移方案

### 6.1 数据库迁移（DTS）

```yaml
# DTS数据迁移流程

# 1. 前置检查
# - 源库账号权限: SELECT, SHOW VIEW, REPLICATION SLAVE, REPLICATION CLIENT
# - 目标库空间: >= 源库数据量 × 1.2
# - 网络带宽: 评估数据量和迁移窗口

# 2. 创建DTS迁移任务
迁移类型: 数据迁移（全量 + 增量）
源库: MySQL 5.7 (IDC)
目标库: RDS MySQL 8.0 (阿里云)
迁移对象: 选择需要迁移的库表

# 3. 迁移步骤
Step 1: 结构迁移（表结构、索引、约束）
Step 2: 全量迁移（历史数据）
Step 3: 增量同步（实时Binlog同步）
Step 4: 数据校验（源库和目标库数据一致性）
Step 5: 业务切换（停写 → 追平 → 切换）

# 4. 切换流程
# a. 应用停写（或设置只读）
# b. 等待增量同步追平（延迟 < 1秒）
# c. 数据校验通过
# d. 修改应用数据库连接指向RDS
# e. 恢复写入
# f. 观察确认
```


## 8. 成本优化策略

### 8.1 实例购买策略

```yaml
# 成本优化矩阵

# 计费模式选择
按量付费:
  适用: 开发测试、临时负载、不可预测流量
  节省: 0% (灵活)

包年包月:
  适用: 稳定业务、长期运行
  节省: 30-50% (1年) / 50-70% (3年)

抢占式实例:
  适用: 无状态、可中断任务、大数据计算
  节省: 50-90%
  注意: 可能被回收，需要做好容错

节省计划:
  适用: 多种实例混合使用
  节省: 20-40%

# 推荐组合
生产环境: 包年包月（基础负载） + 按量付费（弹性部分）
开发测试: 抢占式实例 + 按量付费
批处理:  抢占式实例
```

### 8.2 存储分层

```yaml
# 存储成本优化

OSS存储分层:
  标准存储: 频繁访问（热数据）
  低频访问: 30天不访问
  归档存储: 60天不访问（需解冻）
  冷归档: 180天不访问
  深度冷归档: 365天不访问

# 生命周期规则
自动将90天前的日志转为低频存储
自动将180天前的备份转为归档存储
自动删除365天前的临时文件

ECS磁盘:
  系统盘: cloud_essd (PL0)
  数据盘: cloud_essd (PL0/PL1根据IO需求)
  冷数据: 高效云盘
```
