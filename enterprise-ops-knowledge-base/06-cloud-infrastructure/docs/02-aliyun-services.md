# 阿里云核心服务详解

## 1. 概述

阿里云作为国内最大的公有云服务商，提供了丰富的云产品体系。本文将从运维角度详细介绍企业常用的核心服务，包括服务选型、配置要点、运维最佳实践和常见问题处理。

## 2. 计算服务

### 2.1 ECS (弹性计算服务)

ECS 是阿里云最核心的计算服务，提供可伸缩的云服务器。

**实例规格族：**

| 规格族 | 特点 | 适用场景 | 示例 |
|--------|------|----------|------|
| 通用型 (g) | CPU:内存 = 1:4 | Web 服务器、应用服务器 | ecs.g7.2xlarge |
| 计算型 (c) | CPU:内存 = 1:2 | 批处理、高性能计算 | ecs.c7.4xlarge |
| 内存型 (r) | CPU:内存 = 1:8 | 数据库、缓存 | ecs.r7.2xlarge |
| GPU 型 | 附带 GPU 卡 | AI 训练、视频处理 | ecs.gn7-c12g1.3xlarge |
| 突发性能 (t) | CPU 积分制 | 开发测试环境 | ecs.t6-c1m1.large |

**存储选型：**

```
高效云盘 → 一般业务（IOPS 5000，吞吐 150MB/s）
SSD 云盘  → 中等 IO（IOPS 20000，吞吐 300MB/s）
ESSD PL0 → 高 IO（IOPS 10000，吞吐 180MB/s）
ESSD PL1 → 超高 IO（IOPS 50000，吞吐 350MB/s）
ESSD PL2 → 极高 IO（IOPS 100000，吞吐 750MB/s）
```

**运维要点：**

1. **镜像管理**：使用自定义镜像标准化部署，配合 Packer 自动构建
2. **标签管理**：为所有实例打标签（环境、项目、负责人），便于资源管理和成本分摊
3. **自动伸缩**：配置伸缩组，基于 CPU、内存或自定义指标自动增减实例
4. **定期巡检**：检查实例状态、磁盘使用率、安全组规则

### 2.2 ACK (容器服务 Kubernetes 版)

ACK 是阿里云托管的 Kubernetes 服务，适合微服务架构。

**集群类型：**
- **托管版**：阿里云管理 Master 节点，用户只需管理 Worker 节点
- **专有版**：用户完全管理所有节点，灵活性最高
- **Serverless 版**：无需管理节点，按 Pod 实际使用计费

**架构建议：**

```
                    ┌─────────────────┐
                    │   ACK 集群       │
                    ├─────────────────┤
                    │  Master (托管)   │
                    │  - API Server   │
                    │  - etcd         │
                    │  - Scheduler    │
                    ├─────────────────┤
                    │  Worker 节点池   │
                    │  - 应用 Pod      │
                    │  - 中间件 Pod    │
                    ├─────────────────┤
                    │  节点池配置      │
                    │  - 通用型 (Web)  │
                    │  - 内存型 (DB)   │
                    │  - GPU 型 (AI)   │
                    └─────────────────┘
```

### 2.3 函数计算 FC

函数计算是无服务器计算服务，按实际执行次数和时长计费。

**适用场景：**
- 事件驱动任务（OSS 文件处理、消息队列消费）
- API 接口（轻量级 REST API）
- 定时任务（替代 Cron）
- 数据处理管道

## 3. 数据库服务

### 3.1 RDS (关系型数据库服务)

RDS 支持 MySQL、SQL Server、PostgreSQL、MariaDB。

**高可用架构：**

```
┌─────────────────────────────────────┐
│           RDS 高可用版               │
│  ┌───────────┐    ┌───────────┐     │
│  │  主实例    │───→│  备实例    │     │
│  │ (AZ-1)    │同步│ (AZ-2)    │     │
│  └───────────┘    └───────────┘     │
│         │                           │
│  ┌──────▼──────┐                    │
│  │  只读实例    │  ← 读写分离        │
│  └─────────────┘                    │
└─────────────────────────────────────┘
```

**版本选择建议：**
- MySQL 8.0：新项目首选，支持窗口函数、CTE、JSON 增强
- MySQL 5.7：存量系统维持，注意已停止官方支持
- PostgreSQL：需要 GIS、JSONB、全文检索时选择

**关键参数：**
```sql
-- InnoDB 缓冲池（建议物理内存的 70%）
innodb_buffer_pool_size = 48G

-- 连接数
max_connections = 5000

-- 慢查询阈值
long_query_time = 1

-- binlog 保留时间
expire_logs_days = 7
```

### 3.2 Redis (云数据库 Redis)

**架构模式：**
- **标准版**：主从架构，适合中小规模
- **集群版**：分片架构，支持水平扩展
- **读写分离版**：自动读写分离，适合读多写少

**内存管理建议：**
```
maxmemory-policy: allkeys-lru  # 通用缓存场景
maxmemory-policy: volatile-lru  # 有过期时间的 key
maxmemory-policy: noeviction    # 数据不能丢失场景
```

### 3.3 MongoDB (文档数据库)

**副本集配置：**
- 3 节点副本集（1 主 2 从）为最小生产配置
- 建议开启 oplog，窗口大小至少 24 小时
- 读写分离：readPreference=secondaryPreferred

## 4. 网络服务

### 4.1 VPC (专有网络)

VPC 是阿里云的虚拟网络，所有云资源都部署在 VPC 内。

**CIDR 规划建议：**

```
生产环境: 10.1.0.0/16 (65534 个 IP)
开发环境: 10.2.0.0/16
测试环境: 10.3.0.0/16

子网划分示例 (10.1.0.0/16):
├── 10.1.1.0/24  → 应用层 (AZ-1)
├── 10.1.2.0/24  → 应用层 (AZ-2)
├── 10.1.10.0/24 → 数据层 (AZ-1)
├── 10.1.11.0/24 → 数据层 (AZ-2)
├── 10.1.20.0/24 → 中间件 (AZ-1)
└── 10.1.21.0/24 → 中间件 (AZ-2)
```

### 4.2 SLB (负载均衡)

**类型选择：**
- **CLB (经典负载均衡)**：四层 + 七层，成熟稳定
- **ALB (应用型负载均衡)**：七层为主，支持高级路由
- **NLB (网络型负载均衡)**：四层高性能，超高并发

**健康检查配置：**
```
检查间隔: 2 秒
超时时间: 2 秒
健康阈值: 3 次
不健康阈值: 3 次
```

## 5. 存储服务

### 5.1 OSS (对象存储)

**存储类型：**

| 类型 | 适用场景 | 最小存储时间 | 成本 |
|------|----------|-------------|------|
| 标准存储 | 频繁访问 | 无 | 高 |
| 低频访问 | 月访问 < 1次 | 30 天 | 中 |
| 归档存储 | 年访问 < 1次 | 60 天 | 低 |
| 冷归档存储 | 极少访问 | 180 天 | 极低 |

**生命周期规则示例：**
```xml
<LifecycleConfiguration>
  <Rule>
    <ID>archive-old-data</ID>
    <Prefix>data/</Prefix>
    <Status>Enabled</Status>
    <Transition>
      <Days>30</Days>
      <StorageClass>IA</StorageClass>
    </Transition>
    <Transition>
      <Days>90</Days>
      <StorageClass>Archive</StorageClass>
    </Transition>
    <Expiration>
      <Days>365</Days>
    </Expiration>
  </Rule>
</LifecycleConfiguration>
```

## 6. 安全服务

### 6.1 RAM (访问控制)

**最佳实践：**
- 遵循最小权限原则
- 为每个应用创建独立的 RAM 角色
- 使用 STS 临时凭证替代长期 AccessKey
- 开启 MFA 多因素认证

### 6.2 云安全中心

**核心功能：**
- 漏洞扫描与修复
- 入侵检测与告警
- 基线检查（CIS Benchmark）
- 资产指纹管理

## 7. 监控服务

### 7.1 云监控 (CloudMonitor)

**关键监控指标：**

```
ECS: CPU利用率、内存使用率、磁盘IO、网络流量
RDS: 连接数、QPS、慢查询、主从延迟
Redis: 内存使用率、连接数、命中率、QPS
SLB: 后端健康状态、并发连接数、请求速率
OSS: 存储量、请求次数、流量
```

**告警配置建议：**

| 指标 | 告警阈值 | 紧急程度 |
|------|----------|----------|
| CPU > 80% | 持续 5 分钟 | 警告 |
| CPU > 95% | 持续 2 分钟 | 严重 |
| 内存 > 90% | 持续 5 分钟 | 严重 |
| 磁盘 > 85% | 持续 10 分钟 | 警告 |
| RDS 连接数 > 80% | 持续 3 分钟 | 严重 |
| 主从延迟 > 10s | 持续 1 分钟 | 严重 |

## 8. 总结

阿里云服务选型的核心原则：

1. **按需选择**：不是越贵越好，适合业务场景最重要
2. **高可用优先**：生产环境至少使用高可用版
3. **安全内置**：RAM + 安全组 + 加密，缺一不可
4. **监控先行**：上线前先配置好监控告警
5. **成本可控**：合理使用包年包月 + 按量付费组合
