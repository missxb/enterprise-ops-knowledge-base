# 企业网络架构设计

## 1. 网络架构概述

企业网络架构是整个 IT 基础设施的骨架。一个设计良好的网络架构需要满足高可用、高性能、安全可控、弹性扩展四大核心诉求。在实际项目中，网络架构的设计往往决定了后续运维的复杂度和业务的稳定性。

### 1.1 网络架构演进

企业网络架构经历了从传统三层架构到 Spine-Leaf 架构，再到云原生网络的演进：

**传统三层架构（Core-Distribution-Access）**：
- 核心层（Core）：负责高速转发，连接各汇聚交换机
- 汇聚层（Distribution）：策略执行、路由汇总
- 接入层（Access）：终端设备接入

这种架构在传统数据中心广泛使用，但存在 STP 收敛慢、东西向流量路径长等问题。

**Spine-Leaf 架构**：
- Spine 交换机：骨干层，每个 Leaf 都连接到所有 Spine
- Leaf 交换机：接入层，服务器双上联到两个 Leaf
- 无阻塞、低延迟、易于水平扩展

现代数据中心普遍采用 Spine-Leaf 架构，配合 ECMP 实现流量均匀分布。

**云原生网络架构**：
- Overlay 网络（VXLAN/Geneve）实现大二层扩展
- Service Mesh 实现应用层流量治理
- CNI 插件管理 Pod 网络

### 1.2 网络分区设计

企业网络按安全等级划分为多个区域：

### 1.3 IP 地址规划

IP 地址规划是网络设计的基础工作，需要遵循以下原则：

**CIDR 规划示例**：

| 区域 | 网段 | 用途 | 预留空间 |
|------|------|------|----------|
| DMZ | 10.1.0.0/16 | 对外服务 | 可扩展到 /15 |
| 生产应用 | 10.2.0.0/16 | 应用服务器 | 可扩展到 /15 |
| 数据库 | 10.3.0.0/16 | 数据存储 | 可扩展到 /15 |
| 管理网 | 10.4.0.0/16 | 运维管理 | 可扩展到 /15 |
| 容器网络 | 172.16.0.0/12 | K8s Pod CIDR | 1M+ Pod |
| Service Mesh | 192.168.0.0/16 | 内部服务 | 灵活分配 |

**子网划分原则**：
- 每个业务单元分配独立子网
- 预留 30%-50% 的地址空间供扩展
- 使用 /24 作为最小分配单元
- 避免使用 10.0.0.0/8 中的零散小网段

## 2. 高可用网络设计

### 2.1 冗余设计

**设备级冗余**：
- 核心交换机堆叠或 VPC（Virtual Port Channel）
- 出口路由器双机热备（VRRP/HSRP）
- 负载均衡器主备或集群模式

**链路级冗余**：
- 服务器双网卡绑定（LACP/Mode 4）
- 交换机间多链路聚合
- 双运营商接入（BGP 多线）

**机房级冗余**：
- 同城双活机房（<5ms 延迟）
- 异地灾备机房（RPO<15min）
- DNS 全局负载均衡实现流量调度

### 2.2 负载均衡架构

```
                 ┌─────────────┐
                 │   DNS GLB    │  ← 全局负载均衡
                 └──────┬──────┘
            ┌───────────┼───────────┐
     ┌──────┴──────┐    │    ┌──────┴──────┐
     │  机房 A LB   │    │    │  机房 B LB   │  ← L4 负载均衡
     └──────┬──────┘    │    └──────┬──────┘
            │           │           │
   ┌────────┴─────┐     │   ┌───────┴──────┐
   │  Nginx 集群   │     │   │  Nginx 集群   │  ← L7 反向代理
   └────────┬─────┘     │   └───────┬──────┘
      ┌─────┼─────┐     │     ┌─────┼─────┐
      │     │     │     │     │     │     │
     App   App   App    │    App   App   App  ← 应用服务器
```

### 2.3 网络监控

关键监控指标：

- **链路质量**：丢包率、延迟、抖动、带宽利用率
- **设备状态**：CPU、内存、温度、风扇、电源
- **流量分析**：Top-N 流量、异常流量检测
- **连接状态**：TCP 连接数、新建连接速率、并发连接数

常用监控工具：
- Prometheus + SNMP Exporter 采集网络设备指标
- sFlow/NetFlow 进行流量分析
- Zabbix 进行设备健康监控

## 3. 网络安全架构

### 3.1 边界安全

**防火墙策略**：
- 默认拒绝所有入站流量
- 仅开放业务必需端口
- 使用状态检测而非简单包过滤
- 入侵检测/防御系统（IDS/IPS）联动

**DDoS 防护**：
- 运营商级清洗（黑洞路由/流量牵引）
- CDN 隐藏源站 IP
- 限速策略（SYN Flood 防护、连接数限制）

### 3.2 内部安全

**微分段（Micro-segmentation）**：
- 基于业务逻辑划分安全域
- 每个安全域之间设置防火墙策略
- 容器环境下使用 NetworkPolicy 实现 Pod 级隔离

**零信任架构**：
- 所有访问都需要认证和授权
- 最小权限原则
- 持续验证（不信任网络位置）

### 3.3 网络审计

- 所有网络设备配置变更审计
- 关键网络操作双人复核
- 流量日志保留 6 个月以上
- 定期安全扫描和渗透测试

## 4. 云网络设计

### 4.1 VPC 设计

云环境下的 VPC 规划：

```
VPC: 10.0.0.0/8
├── 公有子网 (10.0.0.0/16)     ← 对外服务，有公网 IP
│   ├── 可用区 A: 10.0.1.0/24
│   ├── 可用区 B: 10.0.2.0/24
│   └── 可用区 C: 10.0.3.0/24
├── 私有子网 (10.1.0.0/16)     ← 应用层，通过 NAT 出网
│   ├── 可用区 A: 10.1.1.0/24
│   ├── 可用区 B: 10.1.2.0/24
│   └── 可用区 C: 10.1.3.0/24
└── 数据子网 (10.2.0.0/16)     ← 数据库，无出网能力
    ├── 可用区 A: 10.2.1.0/24
    ├── 可用区 B: 10.2.2.0/24
    └── 可用区 C: 10.2.3.0/24
```

### 4.2 混合云网络

混合云场景下的网络互联：

- **专线接入**：高带宽、低延迟，适合核心业务
- **VPN 互联**：成本低、部署快，适合非实时业务
- **SD-WAN**：智能选路、多链路聚合

### 4.3 Kubernetes 网络

K8s 网络模型的核心要求：
- 每个 Pod 有独立 IP
- Pod 之间可以直接通信（不需 NAT）
- Node 与 Pod 之间可以直接通信

常用 CNI 插件对比：

| 特性 | Calico | Cilium | Flannel | Weave |
|------|--------|--------|---------|-------|
| 网络模式 | BGP/VXLAN | eBPF/VXLAN | VXLAN | VXLAN |
| NetworkPolicy | ✅ | ✅ | ❌ | ✅ |
| 性能 | 高 | 极高 | 中 | 中 |
| eBPF | ❌ | ✅ | ❌ | ❌ |
| 适用规模 | 大 | 极大 | 中 | 中 |

## 5. 网络自动化

### 5.1 自动化工具选型

- **Ansible**：无代理、适合配置管理和批量操作
- **Terraform**：适合云资源编排
- **Netmiko/NAPALM**：Python 网络设备自动化库
- **Nornir**：并行网络自动化框架

### 5.2 GitOps 网络管理

将网络配置纳入 Git 管理：
1. 网络设备配置模板化
2. 变更通过 PR 审核
3. CI/CD 自动下发配置
4. 配置漂移检测与自动修复

## 6. 常见网络问题与排查

| 问题 | 可能原因 | 排查命令 |
|------|---------|---------|
| 丢包 | 链路故障、MTU 不匹配、ACL 拒绝 | `ping`, `traceroute`, `tcpdump` |
| 延迟高 | 路由环路、拥塞、DNS 慢 | `mtr`, `tcptraceroute` |
| 连接超时 | 防火墙策略、端口未监听 | `telnet`, `nc`, `nmap` |
| DNS 解析失败 | DNS 服务异常、配置错误 | `dig`, `nslookup`, `host` |
| 带宽不足 | 流量突增、链路故障 | `iftop`, `nload`, `ss` |
